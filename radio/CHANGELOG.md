# NHK ラジオダウンローダー - 変更履歴

## [2.0.0] - 2026-05-15

### パフォーマンス改善

#### Priority 5: N+1 I/O 問題解決
- **バッチダウンロード判定**: `get_downloaded_episode_keys()` 関数を追加
  - 複数エピソードの保存状態を 1 回のマニフェスト読み込みで判定
  - GUI レンダリング時の繰り返し I/O を排除
  - **効果**: 100 エピソード表示時の I/O 回数を 100+ 回から 1 回に削減

#### Priority 6: マニフェスト保存の原子性
- **原子的書き込み実装**: `tempfile.mkstemp()` + `Path.replace()` パターン
  - プロセスクラッシュ時のマニフェスト破損を防止
  - 既に実装済みの `cache.py` と同じ安全なパターンを採用

#### Priority 7: エラーハンドリング改善
- **キャッシュ保護**: フェッチ失敗時に空リストを書き込まない
  - 期限切れキャッシュが再利用可能になる
  - ネットワーク一時障害時のユーザー体験を向上

#### Priority 8: サブプロセス管理の統一
- **`run_yt_dlp_subprocess()` 関数**: CLI と GUI 間の重複コードを統一
  - 進捗レポート機能（コールバック方式）
  - キャンセルイベント対応
  - **効果**: 70+ 行のコード重複を排除

#### Priority 9: プロセスハング防止
- **プロセスタイムアウト**: 120 秒でハング検知と強制終了
  - yt-dlp が応答不能に陥った場合の自動リカバリ
  - UI のハングを防止、ユーザー操作を再度可能にする

#### Priority 10: リトライパターン改善
- **指数バックオフ**: リトライ間隔を `[0, 0.1, 0.2]` 秒に
  - 最初のリトライは即座（期限切れキャッシュ同期が成功することが多い）
  - 失敗時は徐々に遅延（ファイルシステム遅延に対応）
  - **効果**: 成功時に 0.4 秒から 0 秒へ（最初の試行で完了）

#### Priority 11: キャッシュ容量管理
- **ファイルスキャンキャッシュの最適化**: 200 → 100 エントリ
  - メモリ使用量を 150KB 削減（typical: 1.5KB/エントリ）
  - 環境変数 `NHK_RADIO_FILE_SCAN_CACHE_SIZE` で調整可能
  - キャッシュ削除時に debug ログを記録（observability 向上）

#### Priority 12: GUI ポーリング最適化
- **動的ポーリング間隔**: ダウンロード数に応じて自動調整
  - 3+ 件: 50ms（複数ジョブの応答性を優先）
  - 1-2 件: 100ms（CPU 効率を優先）
  - **効果**: CPU 使用率を削減しつつ、複数ダウンロード時は即座に更新表示

### ネットワーク負荷削減

#### Priority 1: yt-dlp リトライ削減
- **socket_timeout**: 60秒 → 30秒（遅延時のフェイルオーバーを迅速化）
- **retries**: 5回 → 2回（段階的リトライで十分）
- **効果**: 最悪リトライ時間を 10 分 → 60 秒に短縮

### コード品質

#### Priority 2: 重複メソッド削除
- **browser.py**: 5 個の重複定義を整理
  - `_handle_browser_shortcut`, `_clear_cache`, `_focus_*` など
  - MRO による暗黙の実装選択を廃止
  - **効果**: 48 行削減、メンテナンス性向上

#### Priority 3-4: マニフェストキャッシング (mtime 検証)
- **キャッシュ形式拡張**: `(timestamp, mtime, data)` に
  - ファイル更新時にキャッシュ自動無効化
  - TTL (10秒) と mtime チェックの併用
  - **効果**: テストでの manifest 直接書き込みにも対応

### テスト・品質保証

- **テストカバレッジ**: 205 個の回帰テスト（pytest）
  - 全体カバレッジ: 79%
  - コア機能: cache, cli, config, core, text, types 100%
  - ダウンロード: downloads 91%
  - GUI: 35-100% (builder 100%, theme 93%, help 99%)
- **自動カバレッジ計測**: 各コミット時に実行
- **CI チェック**: GitHub Actions による自動テスト

### ドキュメント

- ファイル構成の詳細化
