## 1. 非 GUI（core / cli / cache / config / text / downloads / scripts）

### High

**H1. 保存済み判定が、yt-dlp の実際のファイル名と一致しない【再現済】**

場所: `downloads/filesystem.py:107-124`、`text.py:152`

- 何が食い違うか: yt-dlp は `%(title)s` の中の `: ? / " * < > |` を全角の代替文字（`：` `？` `⧸` など）に置き換える。一方、照合する側は `_safe_name` でこれらを `_` に置き換えてから部分一致を取る。このため両者が一致しない。
- 失敗シナリオ: エピソード名が `Q&A: 何？/なぜ?` のとき、`is_episode_downloaded` が False を返す。その結果、次のことが起きる。
  - DL 直後の `sync_episode_download_history` も None を返し、マニフェストに記録されない。
  - CLI では毎回再ダウンロードされ、GUI では未保存として表示される。
  - 語学番組は `Lesson 1: ...` のような題名が多いため、影響は大きい。
- 修正案:
  - 本命: `--print after_move:filepath` で実際のパスを受け取り、マニフェストに記録する。
  - 次善: 照合する側でも `yt_dlp.utils.sanitize_filename` を通す。

**H2. CLI で stdin が EOF になると無限ループする【再現済】**

場所: `cli.py:47-64`、`cli.py:90-110`

- 原因: `except (ValueError, EOFError)` で EOF を捕まえた後もループを続けている。
- 失敗シナリオ: headless 環境で stdin が `/dev/null` やパイプのとき、CPU 100% で「数字を入力してください」を出力し続ける。
- 修正案: `EOFError` は別に捕まえて `return None` で抜ける。

## 2. GUI（`src/nhk_radio/gui/`）

### High

**G1. ワーカーの準備段階で例外が出ると、ジョブが running のまま残り、アプリを閉じられない【コード読解】**

場所: `gui/download_manager.py:97-109`

- 原因: `program_output_dir`、`mkdir`、`download_episode_command` が `try` の外にある。
- 失敗シナリオ:
  1. 外付けディスクが外れている、または権限がない状態で DL を始める。
  2. `OSError` でスレッドが終了するが、`on_result` は呼ばれない。
  3. 行が running のまま止まり、`browser.py:300-308` の `_cancel` が閉じる操作を拒否する。強制終了するしかなくなる。
- 修正案: 準備処理を `try` の中に入れる。`finally` で必ず `failed_one` を通知する。

**G2. ポーリングが早く止まり、完了イベントを取りこぼす**

場所: `download_manager.py:56-61, 107-109, 140-145`、`download_panel.py:151-192`

- (a) `processes[key]` をワーカーの中で登録しているため、最初の 100ms のポーリング時点で `is_active()` が False になりうる。そうなるとポーリングが止まり、以後のイベントは処理されない。`cancel_all` も、まだ登録されていないジョブを中止できない。
- (b) 完了の通知（`on_result`）が `processes.pop` より前にあるため、`done_one` がキューに残ったままポーリングが止まるタイミングの窓がある。テストはこの順序を仕様として固定している。
- 修正案:
  - `start_download` の中で、ロックを取って登録する。
  - `cancel_all` は `cancel_events` を基準に処理する。
  - ポーリングを止める前に、キューを最後にもう一度空にする。

**G3. 保存済み（☑）の判定結果を、古い行の並びに当てはめてしまう**

場所: `listing/episodes.py:87, 97-128`、`browser.py:227-228`

- 原因は 3 つある。
  - 行 ID `episode-{index}` を再描画のたびに付け直している。
  - 古い結果かどうかを番組の一致でしか確認していない。
  - 結果の反映は True を付けるだけで、False に戻さない。
- 失敗シナリオ: 検索欄に 1 文字ずつ入力すると、別のエピソードに ☑ が付く。そこから再生や削除のメニューが有効になってしまう。
- その他: ワーカースレッドから `root.after` を直接呼んでいる（ウィンドウ破棄後は TclError になる）。
- 修正案:
  - 世代番号で古い結果を捨てる。`_populate_generation` と同じ方式が使える。
  - True と False の両方を書き込む。
  - 結果はキュー経由で受け取る。
  - 検索欄の入力処理にデバウンスを入れる。

## 3. テストの弱点

- **往復テストが無い**: ファイル名の照合テストは ASCII の題名で、ファイル名も手書きで作っている。yt-dlp の `prepare_filename` で作ったファイル名を使う往復テストがあれば、H1、M1、M4、M5 は検出できたはずである。
- **並行処理が未検証**: `DownloadManager` の並行動作とポーリング停止を検証するテストが無い。smoke テストは丸ごとモックしている。危うい順序（G2b）は、テストが仕様として固定している。
- **テスト名と中身が合わない**: `test_cancelled_worker_terminates_even_before_output` は runner をモックしているため、terminate が呼ばれることを検証していない。
- **異常系が足りない**: EOF、Ctrl+C、構造が壊れた JSON、HTTP-date 形式の `Retry-After` のテストが無い。
- **型の取り違えを検出できない**: CI に `mypy --check-untyped-defs` を追加するのが、低コストで効果の大きい対策である。

## 4. 良い点

- キャッシュ、マニフェスト、設定が `atomic_write_*`（一時ファイルを書いてから `replace`）で書かれており、書き込み途中のクラッシュに強い。
- キャッシュに schema_version、TTL、型チェックがあり、取得失敗時は stale キャッシュへ段階的にフォールバックする。
- yt-dlp はリスト形式の引数で起動し、`shell=True` を使っていない。API の同時実行数を Semaphore で制限し、バックオフに上限がある。
- ワーカーはキューに put するだけで、UI は `after` のポーリングで取り出す。ワーカーからウィジェットを直接触らない基本方針が守られている（例外は G3）。
- `DownloadManager` と `DataManager` が UI から分離され、tkinter なしで単体テストできる構造になっている。

## 5. 推奨する対応順

1. **H1 + M1 + M5**: DL 時に実際のパスを記録する方式へ切り替え、推測による照合をやめる。誤削除を防ぐうえでも最優先。
2. **G1 + G2**: `download_manager.py` を直す。準備処理を `try` に入れ、登録を `start_download` の中で行い、通知と後片付けの順序を整える。
3. **H2、M2、M3**: EOF と、構造が壊れたファイルに耐えられるようにする。
4. **G3、G4、G6**: ☑ の世代管理、上書き前に元ファイルを削除しないこと、取得中でも閉じられること。
5. **G15 と §0 のカバレッジ設定**: 品質指標を実態に合わせる。
