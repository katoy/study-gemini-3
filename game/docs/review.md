## 2. `index.html` の詳細レビュー

### 2.1 仕様適合性とゲームロジック
- **群島マップ生成と連結性保証 (`generateArchipelago`, `isLandConnected`)**:
  - 7×7（全49マス：陸地40マス、海9マス）の六角形グリッド（odd-r pointy-top）において、左上のプレイヤー港 `(0, 0)` から全陸地マスへ到達可能であることを幅優先探索（BFS）で検証しており、到達不能な孤島が発生しない設計になっている。
  - 両陣営の初期港に隣接するマスへ必ず「森」と「漁場」を配置しており、初期資源（木材4・食料2・石2）とあわせて序盤の資源枯渇・手詰まりを防いでいる。
- **行動ルールとコスト制御 (`getAvailableActionsForTile`, `executeAction`)**:
  - 開拓（木材2）、攻略（食料2＋石1／砦ありは食料4＋石2）、砦建設（石2）、市場建設（木材1＋石1）の4行動が仕様通り実装されている。
  - 「港マスは攻略不可」「資源不足の行動ボタンは `disabled` 化」「1ターン2回までの行動制限」がUI表示と実行ガードの双方で一貫して制御されている。
- **勝利判定 (`checkImmediateDominationVictory`, `finishGameByTurnLimit`)**:
  - 行動ごとの陸地60%（24/40マス）支配による即勝利判定と、全20ターン（両者10回ずつ）終了時の得点判定（所有マス1点・市場2点・砦1点）が正しく動作する。
- **CPU思考ルーチンと非同期演出 (`chooseCpuAction`, `runCpuTurnSequence`)**:
  - **やさしい**: 実行可能な行動からランダム選択。
  - **ふつう**: 即時得点増分に加え、残りターン数と現在の資源希少度を考慮した将来資源価値を計算して最善手を選択。
  - **つよい**: プレイヤーの次ターン開始時の予想資源（現在の食料・石＋次ターン収入）から攻略可能かを判定し、プレイヤーに隣接する自軍重要マスへの「砦」建設を優先する先読みロジックが実装されている。
  - **非同期安全性**: `state.sessionId` によるトークン管理が導入されており、CPUのアニメーション待機中（`sleep` 中）にプレイヤーがタイトルへ戻ったりリトライしたりしても、古い非同期処理が新しいゲーム状態を汚染しないよう保護されている。
